# Releasing

## Versioning

This repository uses semantic versioning for tagged releases.

Release tags should follow the `vMAJOR.MINOR.PATCH` format, for example `v1.2.3`.

## Pre-release Checklist

1. Run `go test ./...`
2. Run `go test -race ./...`
3. Run `go run golang.org/x/vuln/cmd/govulncheck@latest ./...`
4. Run `cd web && npm audit --json`
5. Run `cd web && npm run smoke`
6. Run `go test ./web -run TestAuthenticatedServiceSoak`

## Artifact Expectations

- tagged GitHub Release generated by `.github/workflows/release.yml`
- release notes synthesized from the tagged commit range
- signed checksum manifest for the release archives
- packaged binaries for `web` and `cmd/hashpassword` on the supported release targets
- updated docs if configuration or deployment contracts changed

## Release Workflow

1. Push a tag that matches `v*`.
2. The release workflow builds the binaries for Linux, macOS, and Windows on `amd64` and `arm64`.
3. The workflow generates a tag-specific changelog from the commit history since the previous release tag.
4. The workflow signs the checksum manifest with `cosign` using GitHub OIDC.
5. The workflow publishes the GitHub Release and uploads the archives plus the signed checksum files.

## Breaking Changes

Any breaking change to public library behavior, web authentication, persistence schema, or deployment configuration must be documented in the release notes and migration guidance.

## Manual Validation Before Tagging

The release workflow assumes these checks have already passed on the commit being tagged:

1. `go test ./...`
2. `go test -race ./...`
3. `go run golang.org/x/vuln/cmd/govulncheck@latest ./...`
4. `cd web && npm audit --json`
5. `cd web && npm run smoke`
6. `go test ./web -run TestAuthenticatedServiceSoak`
